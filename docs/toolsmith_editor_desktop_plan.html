Toolsmith Editor Desktop
実装ラン（tinyjs 版）

Live demo 版（Web 版）とは完全に独立した、tinyjs による軽量デスクトップアプリの実装方針書

1方針：Web 版とは別物として構築する

基本方針：Live demo 版（Web 版）とはコードベースを分離し、tinyjs 上で動作する独立したデスクトップアプリとして Toolsmith Editor Desktop を構築する。Web 版の機能を参考にしつつ、デスクトップネイティブな体験を最優先とする。

分離開発とする理由

  • Web 版はブラウザの制約（CORS、ストレージ容量、ファイルシステムアクセスなど）を受けるが、デスクトップ版はそれらを意識しない設計にできる
  • tinyjs の tiny.fs、tiny.dialog、tiny.menu などネイティブ API を最大限活用し、Web 版との互換レイヤーを削減できる
  • Web 版の配信サイズ最適化（PWA、Service Worker、コード分割など）と、デスクトップ版のビルド・署名・配布パイプラインは関心事が異なる
  • 両者を独立させることで、それぞれのプラットフォームに最適な実装を選択できる

2現状の Web 版からの機能継承方針

機能Web 版の実装Desktop 版の方針
リッチテキスト編集 ブラウザ上のエディタコンポーネント 同コンポーネントを流用（フロントエンドは HTML/CSS/JS のため）
Markdown ソース確認 クライアントサイドパーサ 同パーサを流用
自動保存 IndexedDB ローカルファイルシステムへの直接書き出しに変更
Quarto 書き出し ブラウザ内生成 + ダウンロード バックエンドでファイル生成、任意のディレクトリに保存
MUSIC-ABC 再生 Web Audio / プレイヤーライブラリ 同ライブラリを流用。Linux では tinyjs の tiny.audio.sampler 活用を検討

エディタのコア（リッチテキスト ↔ Markdown の変換ロジック、ABC 記法の解釈）は Web 版からそのまま持ち込める。変更が必要なのは「保存先」「ファイル操作」「OS 連携」の周辺部分のみである。

4主要機能の実装計画

4.1 ファイル管理（コア機能）

  • ワークスペースフォルダ：起動時にユーザーにフォルダを選択させ、その配下の .md ファイルを一覧表示する
  • リアルタイム保存：編集内容を即座に該当ファイルへ書き出す（自動保存）。失敗時は UI に警告を表示
  • ファイル監視：外部エディタでの変更を検知し、競合があればユーザーに確認ダイアログを提示
  • ドラッグ＆ドロップ：Finder / Explorer からの .md ファイルドロップで即時オープン
// backend/file.js イメージ
import { watch } from "@tarwin/tinyjs/fs";

export async function openWorkspace(path) {
  const files = await tiny.fs.readdir(path);
  const mdFiles = files.filter((f) => f.endsWith(".md"));
  return mdFiles;
}

export async function saveFile(path, content) {
  await tiny.fs.writeTextFile(path, content);
}

4.2 ネイティブメニュー

  • File：新規 / 開く / 保存 / 別名で保存 / 最近使ったファイル
  • Edit：元に戻す / やり直し / 切り取り / コピー / 貼り付け
  • View：エディタのみ / プレビューのみ / 左右分割
  • Export：Markdown / HTML / Quarto 形式での書き出し

4.3 Quarto 書き出し連携

  • バックエンドで一時ファイルを生成し、システムにインストールされた Quarto CLI を実行（tiny.process.spawn）
  • Quarto が未インストールの場合はダイアログで案内し、HTML 単体書き出しにフォールバック
  • 生成物の出力先フォルダをユーザーに選択させて保存

4.4 MUSIC-ABC 再生

  • Web 版と同じ ABC プレイヤーライブラリをフロンエンドに組み込む
  • Linux 環境では Web Audio のクラックルノイズ問題があるため、tiny.audio.sampler への切り替えを検討
  • macOS / Windows では既存の Web Audio 実装を維持し、プラットフォーム分岐で対応

5軽量化のための施策

5.1 フロントエンドの削減

  • Web 版で使用していたアナリティクス、PWA 関連スクリプト（Service Worker 登録等）は完全に削除
  • フレームワーク（React / Vue 等）を使わず、Vanilla JS + 小さな状態管理ユーティリティで構築
  • Markdown パーサは機能要件を満たす最小実装に絞り、不要なプラグインを外す

5.2 バックエンドの軽量化

  • txiki.js は標準で軽量なため、バックエンドは必要なモジュールのみを読み込む
  • 外部 npm パッケージの利用は最小限に抑え、標準 API で代替可能な処理は自前実装
  • 起動時の初期化処理を短縮し、ウィンドウ表示後に非同期でワークスペース読み込み

5.3 アセット最適化

  • フォントはシステムフォントを優先し、埋め込みフォントは削除（-apple-system、Segoe UI などを利用）
  • アイコンは SVG のみで管理し、PNG を含めない
  • CSS は未使用スタイルを削除し、単一ファイルにバンドル

7技術的リスクと対策

リスク 1：tinyjs のプラットフォーム対応状況

macOS が最も安定しており、Windows / Linux はベータ段階。最初のターゲットを macOS に絞り、動作確認後に他プラットフォームへ展開する方針とする。

リスク 2：Web 版との機能差

Web 版の最新機能が Desktop 版に反映されない可能性がある。エディタコアは共通モジュールとして切り出し、両者で共有できる設計にしておく（Web 版側のリポジトリに core パッケージを置き、submodule または npm リンクで参照）。

リスク 3：ファイル I/O のエラーハンドリング

パーミッション不足、ディスクフル、ファイル競合などのエラーは Web 版では発生しない。すべての tiny.fs 呼び出しを try/catch で囲み、ユーザーへの通知と復旧手順を明確にする。

8まとめ

Live demo 版（Web 版）とは独立した、tinyjs による軽量デスクトップアプリとして Toolsmith Editor Desktop を構築する。

Web のエディタコアを流用しつつ、ファイルシステム、ネイティブメニュー、ダイアログなどデスクトップ特有の機能を txiki.js バックエンドで実装する。保存は IndexedDB ではなくローカルファイルへの直接書き出しとし、エディタらしい「ファイルを開いて編集して保存する」体験を提供する。

まずは macOS 向けに Phase 1〜3 の基本機能（ウィンドウ表示、エディタ移植、ファイル管理）を固め、その後メニュー整備と書き出し機能を追加する。配布サイズは tinyjs の特性を活かし、極力小さく抑えることを目標とする。
